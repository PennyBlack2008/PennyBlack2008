**풀스택 소프트웨어 엔지니어 · AI 에이전트 시스템 설계**

복잡한 비즈니스 요구사항을 운영 가능한 소프트웨어로 구현합니다. 프론트엔드, 백엔드, 데이터베이스, 인프라를 아우르는 개발과 실서비스 운영 경험을 바탕으로, 최근에는 **AI가 생성한 결과를 검증하고 개선하는 엔지니어링 시스템**을 만들고 있습니다.

> 복잡한 문제를 해결하되, 해결책까지 불필요하게 복잡하게 만들지 않습니다.

## 주요 프로젝트

### [Luvle — 모바일 청첩장 서비스](https://github.com/PennyBlack2008/luvle_public)

**Next.js · Spring Boot · MySQL · AWS · Docker**

- 개인 프로젝트로 기획부터 개발, 운영까지 담당
- 300쌍 이상의 커플이 이용한 실서비스
- 이미지 최적화와 S3·CloudFront 활용으로 관련 인프라 비용 약 70% 절감
- 자동화된 모니터링과 장애 대응 체계 구축

### [Spec Schema Org — 자율형 DB 설계·검증 시스템](https://github.com/PennyBlack2008/spec-schema-org)

**Claude Code · Codex · Multi-Agent · SQL**

- 요구사항을 데이터베이스 스키마로 구체화하고 설계 근거를 추적
- 역할을 분리한 AI 에이전트와 레드팀 검토로 예외 시나리오 및 설계 결함 탐색
- 결함 발견 시 관련 설계 단계로 회귀해 수정하고 재검증하는 자동 피드백 루프
- 실제 SQL 실행을 통한 설계 검증

### [Solve Issue Team — AI 기반 개발 워크플로](https://github.com/PennyBlack2008/solve-issue-team)

**GitHub · AI Agents · Development Workflow**

- 개발 이슈를 분석하고 구현·검토하는 과정을 역할별 에이전트로 분리
- 반복 가능한 개발 워크플로와 검증 절차 설계

## 관심 분야

- **실서비스 엔지니어링** — 안정적인 운영, 성능 개선, 유지보수 가능한 구조
- **풀스택 개발** — React/Next.js, TypeScript, Spring Boot/NestJS, MySQL
- **AI 에이전트 엔지니어링** — 오케스트레이션, 컨텍스트 관리, 검증 및 자동 피드백
- **클라우드·자동화** — AWS, Docker, CI/CD, 모니터링

## 개발 철학

기술의 화려함보다 **실제 문제 해결, 검증 가능성, 운영 안정성**을 중요하게 생각합니다.

AI도 코드를 많이 생성하는 것 자체보다, **그 결과를 어떻게 검토하고 신뢰할 수 있게 만드는지**가 중요하다고 봅니다.
